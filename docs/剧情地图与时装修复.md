# 剧情、地图与换装

## 换装原因与修复

真实按钮点击已发送 1657/1659 请求，服务端回复 1658/1660 且 Status=1，存档也已更新。问题发生在客户端：PlayerSystem 初始化时网络事件容器尚未就绪，AddEventHandler 提前返回；收到响应后没有订阅处理器更新 CharacterModel.UseFashionSuitIdx 和试衣间状态。

单机适配器在 Unity 更新线程等待双方初始化。只有 1650/1658/1660 三个处理器都缺失时才重试原生 AddEventHandler，不每帧重复注册。注册后校验状态，并在运行时 status 中报告 playerEventsReady。通过 IL2CPP 元数据查找方法，不把调试用的 RVA 固定地址写入发布模块。

服务器仍负责保存时装方案、隐藏标志与染色数据。方案编号按 0/1/2 对应 I/II/III。实机验证覆盖三个按钮、试穿、关闭重开、服务端读回和保存重启。少量已配置装扮不能代表所有皮肤逐件渲染已验证。

## 剧情与地图

助手提供剧情、地图、永久收集及全部四种操作。在线点击时先生成快照备份、保存退出，按安装的实际表填写合法任务/场景/区域/收集 ID，再重新启动。操作只更新目标进度字段，保留昵称、队伍、装备和装扮。

当前表对应 867 项任务、11 张本地配置地图、73 个区域、3966 条永久收集记录。它们表示可保存的数据覆盖，不等于逐一验证每张地图的完整玩法、全部活动、怪物 AI 和剧情演出。地图必须有 Lolo 场景配置，不能通过虚构 sceneId 生成客户端不存在的关卡。

回退通过操作前备份，恢复是整库操作；不提供任意单任务状态回滚。实际使用说明与备份位置见助手目录。
